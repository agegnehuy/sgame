# Post-Pilot Backlog Framework

Use this framework to convert validated MVP learnings into a clear next-phase roadmap.

## Backlog lanes

## Lane A — Safety/Learning Critical

Criteria:
- Incorrect safety guidance,
- wrong scoring for unsafe behavior,
- mission flow that blocks learning objective.

Target timeline:
- Immediate (next sprint).

## Lane B — Pilot Usability Critical

Criteria:
- Children/facilitators cannot complete intended flow efficiently.
- Major confusion in instructions or controls.

Target timeline:
- Next sprint (high priority).

## Lane C — Stability/Performance

Criteria:
- Device crashes, freezes, severe frame drops, save integrity issues.

Target timeline:
- Continuous, prioritized by impact and reproducibility.

## Lane D — Content Expansion

Criteria:
- Additional missions, richer environments, avatar expansion, Phase 2 onboarding.

Target timeline:
- After pilot quality gates are stable.

## Lane E — Nice-to-Have

Criteria:
- Cosmetic polish, minor UX enhancements, non-critical additions.

Target timeline:
- Backlog only, low priority.

## Prioritization rule

Order by:
1. Safety/learning correctness
2. Pilot operability
3. Reliability and performance
4. New content scope

Never prioritize cosmetic expansion above safety-critical fixes.
